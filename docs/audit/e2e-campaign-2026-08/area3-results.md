## Findings (root cause / severity / fix proposal)

### F1 — CRITICAL: a freshly generated L2 TypeScript project fails its own L1 gate on day 0 (4 red checks)

Verbatim: `cd /tmp/rtm-a3-cWbV && node scripts/check-all.mjs L1` → `EXIT=1`, `=== FAILED: 4 check(s) === typecheck, format, unit tests, min test execution (INV-25)`.

Four independent emission defects, none attributable to user code:

1. **`src/test/contracts/pact-consumer.test.ts` is written against the Pact v3 API but `@pact-foundation/pact@^16.4.0` is pinned.**
   `src/test/contracts/pact-consumer.test.ts(9,3): error TS2353: Object literal may only specify known properties, and 'log' does not exist in type 'PactV4Options'` · `(14,27) Property 'finalize' does not exist on type 'PactV4'` · `(15,28) Property 'verify' does not exist` · `(33,46) Property 'mockService' does not exist` · `(18,35) Expected 0 arguments, but got 1`.
   _Fix:_ regenerate the Pact consumer template against the v4 API (`PactV4` + `.executeTest()`), or pin `@pact-foundation/pact@^12`. Add a compile-check of the emitted template to the bake fixtures.

2. **Vitest globals are used by emitted tests but enabled nowhere.**
   `TS2593: Cannot find name 'describe'` … and at runtime `ReferenceError: describe is not defined` in `unit tests` and `min test execution (INV-25)`. `vitest.config.ts` has no `test.globals: true`; `tsconfig.json` has `"types": ["node"]` with no `"vitest/globals"`.
   _Fix:_ either add `globals: true` + `"types": ["node","vitest/globals"]`, or make every emitted test import from `'vitest'` (the emitted `example.behavioral.test.ts` already does — the pact one does not). Inconsistent within the same generator run.

3. **`src/test/test-setup.ts` imports `testcontainers`, which is not in `package.json`.**
   `TS2307: Cannot find module 'testcontainers' or its corresponding type declarations`.
   _Fix:_ add the devDependency, or emit the file only when a DB test lane is actually provisioned.

4. **Emitted files violate the emitted `.prettierrc.json`.**
   `.prettierrc.json` sets `semi:false, singleQuote:true`; `src/test/test-setup.ts` is emitted with semicolons and double quotes; `CONTRACTS_POLICY.md` carries trailing blank lines prettier strips. Same class at L1 with `--github`: 9 `.github/**` assets fail `prettier --check`.
   _Fix:_ run the emitted formatter over emitted output as the last init step (arbiter already has the config in hand), or extend `.prettierignore` to cover generator-owned assets. A `prettier --check .` assertion in the bake fixtures would have caught this.

**Impact:** the very first command the CLI tells the user to run (`Run: node scripts/check-all.mjs L1 to verify`) fails. This is the product's core promise inverted.

### F2 — CRITICAL: the same project also fails its own L2 gate (5 red checks), all from phantom dependencies and phantom scripts

`node scripts/check-all.mjs L2` → `EXIT=1`, `FAILED: contract tests, db integration tests, playwright e2e, coverage threshold, dead code`.

- **Phantom deps (3):** knip reports `Unlisted dependencies (3): supertest ← __tests__/contract/error-shape.contract.test.ts:2:23; supertest ← tests/api/api.e2e.test.ts:5:21; @playwright/test ← tests/e2e/a11y.spec.ts:6:22`. Runtime confirmation: `Error: Cannot find package 'supertest' imported from …/error-shape.contract.test.ts`.
- **Phantom npm script:** the `playwright e2e` check runs an ephemeral server via `npm run start:test`, which is never emitted → `npm error Missing script: "start:test"` → `[ephemeral-server] readiness timeout` after a wasted **60 s** on every L2 run.
- **`db integration tests`** runs `npx vitest run integration` with no `--passWithNoTests`; with no matching files vitest exits 1 → `No test files found, exiting with code 1`. Structurally always-red for `hasDatabase:true` before the first integration test is written. (Every sibling test lane _does_ pass `--passWithNoTests`.)
- **`dead code`** flags the target's own emitted code: `Unused files (3): src/middleware/410-gone-handler.ts, src/middleware/deprecation.ts, src/middleware/payload-size-limit.ts` + `Unused devDependencies (1): @pact-foundation/pact` + `Unused exported types (1): ProblemDetails`.
- **`coverage threshold`** = cascade (`no coverage summary (run errored or produced no artifact)`).

_Fix:_ add `supertest`, `@playwright/test`, `testcontainers` to the emitted `devDependencies` when the corresponding spec is emitted; emit `start:test` (or gate the playwright check on its existence); add `--passWithNoTests` to the db-integration lane; add the emitted middleware to `knip.json` `ignore` or wire it into the emitted app bootstrap. **A `bake` fixture that runs `npm ci && check-all L2` on a generated target would have caught all five.**

### F3 — CRITICAL: with `node_modules` present, the emitted `commit-msg` githook blocks _every_ commit

`git commit -m "chore: clean commit"` → pre-commit `=== ALL PASSED ===`, then:

```
✖   Please add rules to your `commitlint.config.js`
✖   found 1 problems, 0 warnings
```

Root cause: `.githooks/commit-msg` layer 2 is `npx commitlint --edit "$1"`, guarded only by `[ ! -d "node_modules" ]`. Arbiter emits **no** `commitlint.config.*` and adds **no** commitlint dependency — `npx` net-fetches the binary, finds an empty rule set, and exits 1. Layer 1 (pure-shell conventional-commit check) is correct and would have sufficed alone.

**Reproduced twice, deterministically:** `chore: clean commit` and `chore: second clean commit` both produced identical output (`pre-commit === ALL PASSED ===` then the commitlint rejection, `EXIT=1`, nothing committed). `git log` head unchanged across both attempts.

Precisely what was observed: no `commitlint.config.*` anywhere in the target; no commitlint entry in `package.json`; no `commitlint` in the target's `node_modules/.bin`. `npx --no-install commitlint --version` still resolves `@commitlint/cli@21.2.1` from this machine's **global npx cache** (`~/.npm/_npx`), i.e. the binary came from outside the project. The conclusion holds either way: with a cached copy `npx` runs and exits 1 on the empty rule set; without one it either fetches from the network or fails to resolve — in all three cases the exit code is non-zero and **every commit is blocked**.

Secondary concern: a git hook that resolves and may download a package from the network on every commit is a supply-chain smell.

_Fix (lazy):_ delete layer 2 — layer 1 already enforces the same contract with zero dependencies. _Fix (full):_ emit `commitlint.config.mjs` extending `@commitlint/config-conventional` and add both packages to `devDependencies`, and change the guard to `command -v commitlint` / `test -f commitlint.config.*` instead of `-d node_modules`.

### F4 — HIGH: the emitted CI's _required_ PR job calls npm scripts that were never emitted

`01-pr-fast.yml:92-93` job `Lint + Typecheck` runs `npm run typecheck` and `npm run lint`; `02-pr-extended.yml:183` runs `npm run test:e2e:bake`; `02-pr-extended.yml` documents `npm run build`. The emitted `package.json` has only `[test, test:unit, test:contract, test:integration, test:behavioral, format, prepare]`. The first PR opened on a generated repo fails CI with `npm error Missing script: "typecheck"`.

Note the asymmetry: `check-all.mjs` invokes the same tools **directly** (`npx tsc --noEmit`, `npx eslint src`) — so the local gate is green while CI is red. actionlint cannot see this (it does not resolve `npm run` targets), which is exactly why the phantom-ref scan is worth adding as a gate.

_Fix:_ emit `typecheck`/`lint`/`build` npm scripts (delegating to the same commands `check-all` uses), or change the workflow steps to `node scripts/check-all.mjs L1`. Add a generator-side assertion "every `npm run X` in an emitted workflow exists in the emitted `package.json`".

### F5 — HIGH: the emitted `check-no-unused-exports` hook blocks every `.ts` edit in a day-0 project

Editing _any_ TypeScript file in T-L2 → `EXIT=2  Unused exports detected (knip): src/middleware/error-handler.ts:7 — ProblemDetails / Remove unused exports before saving.` The offending export is arbiter's own emitted code. A developer's first edit is blocked by a violation they did not introduce and can only clear by deleting generated code.

Related, same file: the L1 gate warns `src/middleware/error-handler.ts 54:3 warning Unused eslint-disable directive (no problems were reported from 'no-console')` — a second self-inconsistency in the same emitted file.

_Fix:_ make `ProblemDetails` a used export (or `export type` + knip `ignoreExportsUsedInFile`), drop the stale `eslint-disable`, and add "hooks are silent on a virgin tree" to the functional fixtures.

### F6 — HIGH: at L1, secret scanning and PII scanning are silently absent (TS _and_ python)

`arbiter init -y --level L1` sets `features.securityScanning=false`. Consequence, proven: an `AKIAIOSFODNN7EXAMPLE` string plus a PII email in `src/violation.py` → `node scripts/check-all.mjs L1` → `EXIT=0`, fully green. `runCheck` inventory for T-PY and T-L1 contains no `secret scan`, no `PII scan`, no `gitleaks`. Two distinct sub-claims, verified separately: (a) **T-PY (python L1)** — `scripts/check-secret-scan.mjs` _is_ emitted but unwired (documented REVERSE rationale in `scripts/optional-emissions.json`), and `scripts/pii-scan.mjs` is **not emitted at all** (`ls` → no such file); (b) **T-L1 (TS L1)** — verified **unwired only** (`grep -c "runCheck('PII scan'|runCheck('secret scan'" scripts/check-all.mjs` → `0`); whether the two scripts are emitted there was not checked.

The design intent is defensible (L1 = gentlest tier), but nothing in the init output or the emitted docs tells the user "your gate does not scan for secrets". Secret scanning is the one control whose absence is unrecoverable — a leaked key cannot be un-leaked by upgrading to L2 later.

_Fix:_ keep secret scan **always on** regardless of level (it is a ~20 ms pure-node scan with zero toolchain requirement), or at minimum print a warning at init and in `arbiter status` when `securityScanning=false`. Emit `pii-scan.mjs` for every language, not just TS.

### F7 — MED: `any` is trivially bypassable with a bare `eslint-disable-next-line`, no rationale, no expiry

`// eslint-disable-next-line @typescript-eslint/no-explicit-any` + `const sneaky: any = {z:1}` → L1 gate `EXIT=0`, fully green. The emitted `inline suppressions` gate only parses `arbiter-suppress(INV-NN, until=…, reason=…, owner=…)` directives and is blind to native linter pragmas (eslint, ruff `# noqa`, etc.).

_Fix:_ extend `check-inline-suppressions.mjs` to treat unexplained native pragmas as findings (require an adjacent `arbiter-suppress` or a `-- reason:` trailer), or add a ratchet on the pragma count. The `check-no-any.mjs` **hook** still catches the edit, so the bypass only survives if the file is written outside the agent — which is exactly the human-developer path.

### F8 — MED: `npm test` is never rewired in a governed TS project

Emitted `package.json` keeps npm's default `"test": "echo \"Error: no test specified\" && exit 1"` while adding `test:unit`, `test:contract`, `test:integration`, `test:behavioral`. The most reflexive command in the Node ecosystem is a guaranteed failure in a governed project. _Fix:_ set `"test": "vitest run"` or `"test": "npm run test:unit"`.

### F9 — MED (expectation, not defect): a default `arbiter init` emits no CI at all

Without `--github` (and without gh auth), `permitGitHub:false` and `.github/` is not created — no workflows, no PR template, no CODEOWNERS, no dependabot. Consistent with REQ-012's "zero API calls by default", but the "GH Actions workflows generated and internally valid" promise (REQ-007) is opt-in and the init summary never says so. Eight anti-drift guards then ship present-but-unwired for exactly this reason (each with an explicit rationale — the mechanism is honest, the discoverability is not). _Fix:_ one line in the init summary: `CI workflows: not generated (re-run with --github to add them)`.
