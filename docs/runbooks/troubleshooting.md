# Troubleshooting Runbook — arbiter

_Generated by arbiter. Update symptom table for your service._

## § 1 — Health & Smoke Check

Verify the service is alive before any investigation.

```bash
# Liveness + readiness probes
curl -sf https://<host>/health/liveness  | jq .
curl -sf https://<host>/health/readiness | jq .

# Full health (includes dependency indicators)
curl -sf https://<host>/health | jq .
```

Expected response: HTTP 200 with `{"status": "UP"}`.

## § 2 — Symptom-Based Diagnosis

| Symptom                    | Likely Cause          | First Action                              |
| -------------------------- | --------------------- | ----------------------------------------- |
| 503 / connection refused   | Service not running   | Check process / container status          |
| 500 Internal Server Error  | Bug in request path   | Check application logs                    |
| Slow responses (p99 > SLA) | DB / cache contention | Check DB connections, slow query log      |
| Authentication failures    | Token config mismatch | Verify auth provider and client config    |
| High memory / OOM kill     | Memory leak           | Heap dump + restart; profile offline      |
| Message queue backlog      | Consumer stopped      | Restart consumer; check dead-letter queue |
| Dependency unhealthy       | External service down | Check third-party status page             |

## § 3 — Log Investigation

```bash
# Application logs (substitute with your platform)
# Azure Container Apps
az containerapp logs show --name <app-name> --resource-group <rg> --follow

# Kubernetes
kubectl logs -f deployment/<deployment-name> --tail=100

# Filter for errors
# ... | grep -E "ERROR|Exception|WARN"
```

Common log patterns to look for:

- `Connection refused` → database or cache not reachable
- `Timeout` → slow query or overloaded dependency
- `OutOfMemoryError` → heap exhaustion
- `NullPointerException` / `TypeError` → code bug in request path

## § 4 — Database Checks

```bash
# Check active connections
# PostgreSQL
psql -c "SELECT count(*), state FROM pg_stat_activity GROUP BY state;"

# Check for long-running queries (>30s)
psql -c "SELECT pid, now() - query_start AS duration, query FROM pg_stat_activity WHERE state = 'active' AND now() - query_start > interval '30 seconds';"

# Kill a blocking query
psql -c "SELECT pg_terminate_backend(<pid>);"
```

## § 7 — Recovery Actions by Category

### Application crash / restart loop

```bash
# Force restart the container / pod
# Azure Container Apps
az containerapp revision restart --name <app-name> --resource-group <rg>

# Kubernetes
kubectl rollout restart deployment/<deployment-name>
```

### Database connection pool exhausted

1. Restart the application to release connections
2. Investigate active connection count
3. Tune pool size if demand legitimately increased

### Circuit breaker open

1. Identify which downstream service triggered the circuit breaker
2. Verify downstream service health
3. Circuit will close automatically after cooldown period (or restart app to force reset)
