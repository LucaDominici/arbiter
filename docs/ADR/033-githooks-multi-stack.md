# ADR-033: Generated Githooks for All Language Stacks (INV-37)

**Status:** Accepted
**Date:** 2026-05-05
**Issues:** #401

## Context

Arbiter generated rich Claude Code hook configurations (`.claude/hooks/`) for target projects, but had no equivalent for native git hooks. This left a bypass surface for any editor other than Claude Code: a developer using VS Code, vim, or a plain terminal could commit or push without running any quality gate. The L1/L2 gates existed as scripts (`check-all.mjs`) but were not wired to `git commit` or `git push` for non-Claude-Code workflows.

## Decision

Add `src/generators/githooks.ts` — an always-on generator emitting a `.githooks/` directory for all five supported language stacks (TypeScript, Java, Kotlin, Rust, Go, Python):

- **`.githooks/pre-commit`** — runs the L1 gate (`node scripts/check-all.mjs L1` for Node stacks; `./scripts/check-all.sh L1` for non-Node stacks). Exits non-zero on failure, blocking the commit.
- **`.githooks/pre-push`** — runs the L2 gate. Exits non-zero on failure, blocking the push.
- **`.githooks/commit-msg`** — validates conventional commit format. TypeScript uses `npx commitlint`; non-Node stacks use a `grep`-based soft check (documented gap — see Consequences).

**Hook installation:**

- TypeScript projects: auto-installed via a `prepare` script added to `package.json` (`git config core.hooksPath .githooks`). Every `npm install` activates the hooks.
- Non-Node projects (Java, Kotlin, Rust, Go, Python): a `scripts/setup-hooks.sh` script is generated. Developers run it once after clone; the onboarding section of `AGENTS.md` references it.

**Verify probe:** `src/compatibility/probe.ts` gains a `probeHooksPath` function. If `.githooks/pre-commit` exists but `core.hooksPath` is not configured to `.githooks`, it emits a `ProbeResult` with `status: "warning"` and a remediation hint. If `.githooks/` is absent entirely, the probe returns null (silent skip — no hooks generated yet).

**INV-37** added to `src/invariants/catalog.ts` and `AGENTS.md` §Invariants.

## Non-goals

- **Server-side `--no-verify` blocking:** Branch protection and status checks (ADR-007) are the mechanism for that. Githooks are a client-side first-line gate.
- **Husky / lint-staged integration:** Arbiter generates its own minimal hook scripts to avoid runtime dependencies on third-party hook managers.
- **Per-language commitlint equivalents:** Only TypeScript generates a full `commitlint` config. Other stacks use a `grep` regex for the conventional commit prefix, which is less precise (documented gap).

## Consequences

- Every `git commit` and `git push` on a project generated by arbiter now runs the quality gate, regardless of editor. Closes the non-Claude-Code bypass surface.
- The `commit-msg` hook on non-Node stacks (Java, Kotlin, Rust, Go, Python) is a soft `grep` check — it catches blatant format violations but cannot enforce full commitlint scope/type validation. A follow-up issue should evaluate a cross-platform commitlint alternative (e.g., a compiled binary or a `node` availability check).
- Developers on existing clones of generated projects must run `git config core.hooksPath .githooks` (or `npm install` for Node) once after updating. The probe warning surfaces this automatically via `arbiter verify`.
- Adds INV-37 to the governance catalog; any future generator that replaces or modifies `.githooks/` must satisfy INV-37.
