# CI Tier Exceptions — Self-Dogfood Exemptions

> **Status**: active during the #867 dual-run window
> **Owner**: arbiter team
> **Scope**: `.arbiter/workflow-exemptions.json` — the data; this file — the rationale.

## Why this file exists

The self-dogfood gate (`scripts/check-arbiter-self-dogfood.mjs`, INV-75/76) counts action-pin and workflow-permissions violations across **all** `.github/workflows/*.yml` files in this repo. During the multi-PR migration from arbiter's legacy 18-workflow set to the canonical 8-tier set, both sets coexist. Listed files are temporarily excluded from the gate's violation count.

Every exemption is paired with a **sunset condition** — the concrete change after which the entry must be removed. PRs that grow this list without a sunset condition are rejected at review.

## Active exemptions

### `actionPinsExempt`

These 8 tier files are generated by arbiter from `src/templates/github/workflows/*.ejs`. Templates use tag refs (`@v4`, `@v5`, `@stable`) because pinning to a specific SHA inside a template would freeze every generated project to that SHA. SHA pinning of the rendered consumer files is the responsibility of a downstream step (Renovate or release-time post-process).

| `.github/workflows/01-pr-fast.yml`        | Renovate's GitHub-Actions config lands and rewrites `@v4`→SHA on the rendered file.                                                                 |
| `.github/workflows/02-pr-extended.yml`    | Same as above.                                                                                                                                      |
| `.github/workflows/03-human-approval.yml` | Same as above.                                                                                                                                      |
| `.github/workflows/05-release.yml`        | Same as above.                                                                                                                                      |

Empty. The 8 tier templates emit explicit top-level `permissions:` blocks; there is no reason to exempt them from INV-76 enforcement.

## How to add an exemption

1. Add the file path to the appropriate list in `.arbiter/workflow-exemptions.json`.
2. Add a row to the table above with a **concrete** sunset condition (not "later", not "TODO"). If you cannot state the sunset, do not add the exemption.
3. Reference the exemption in the PR description that introduces it.
4. The PR that satisfies the sunset condition removes both the JSON entry **and** the table row in the same commit.

## How to remove an exemption

Delete the JSON entry **and** the table row in the same commit. Run `node scripts/check-arbiter-self-dogfood.mjs` to confirm the gate still passes; refresh the baseline with `--refresh-baseline` only if the count actually shrank.
