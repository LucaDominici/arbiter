# arbiter Positioning

**Issue:** #665

## No ROI Claims

arbiter makes no quantitative ROI claims. You will not find statements like:

- "Saves X hours per sprint"
- "Y% fewer bugs"
- "Z× faster code reviews"

This is deliberate.

### Why

Quantitative claims of this form require controlled experiments that do not exist for this category of tooling. Variables like team experience, codebase age, delivery pressure, and existing process maturity all confound any measurement. Publishing a number without that context is misleading — even if the number came from a real project.

This position is not humility for its own sake. It is intellectual honesty. arbiter is engineering infrastructure; its value accrues slowly through consistency, not in a single sprint.

### What We Do Claim

- arbiter generates governance configs that encode your team's agreed-upon rules.
- Those rules are enforced mechanically, not by memory or convention.
- Mechanical enforcement reduces the variance between "what we said we'd do" and "what we actually do."
- Whether that matters for your team, and by how much, is something only you can measure.

If you want to measure it, see [How to Measure arbiter Value Yourself](PRODUCT/MEASUREMENT-GUIDE.md).
