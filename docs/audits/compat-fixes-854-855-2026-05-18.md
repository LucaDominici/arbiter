# Compatibility-Layer Fixes — #854 + #855

**Date:** 2026-05-18
**Origin:** Sweep 5 audit MAJOR findings (docs/audits/sweep5-compatibility-2026-05-18.md, closes #118 umbrella).

## Bugs fixed

### M1 — `matches()` silent-pass on unparseable constraint (#854)

**Before:** `satisfies()` returned `false` on any constraint regex miss (`^18`, `~18`, `18.x`, bare `18`, empty range). `matches()` then reported "version X.Y outside range", blaming the user's tool for a matrix-author bug.

**After:** new `UnparseableConstraintError` thrown from `satisfies()` whenever the constraint cannot be parsed. `matches()` propagates. New `validateRanges()` helper batch-checks every range against a sentinel version. `probe.ts` wires `assertMatrixRangesParseable()` at module load — typos in `matrix.json` now crash boot with a precise message instead of silently misleading users at probe time. `probeTool` catch maps the thrown error to `status:failed` with `matrix-bug:` prefix so the failure mode is visible.

### M2 — Build probes ignore stderr on zero exit (#855)

**Before:** `runBuildProbe` reported `status:passed` whenever the subprocess didn't throw. `tsc --noEmit`, `cargo check`, and `go build -n` can exit 0 with compiler diagnostics on stderr; users saw green probes for projects with real errors.

**After:** `runBuildProbe` inspects `result.stderr` after a clean exit. Stderr matching any `CompilerErrorPatterns` regex (`error[E\d+]:`, `TS\d{4,}:`, `FAILED`, `fatal error`, `compilation (failed|error)`) downgrades the result to `status:failed` with the first 500 chars in the reason. Non-error stderr (deprecation warnings, etc.) keeps `status:passed` but surfaces a `stderr warnings` trail so it isn't lost.

## Test coverage

11 new tests across 2 files:

- `__tests__/compatibility/matcher.test.ts`: 6 unparseable-constraint throw cases (empty, `^18`, `~18`, `18.x`, bare `18`, mixed range) + 1 error-message-shape assertion + `validateRanges` happy-path / failure-list / shape.
- `__tests__/compatibility/probe.test.ts`: 3 cases for `runBuildProbe` — TS diagnostic via stderr, cargo `error[E0277]:` via stderr, plain deprecation warning passes with trail.

Total compatibility test count: 105 (was 94).

## Behavioural changes (potentially observable)

- **Matrix-typo crash on boot.** A previously-silent bad `matrix.json` now throws an error at import time. The matrix.json shipped with this PR was validated; downstream forks that have monkey-patched `matrix.json` may see new errors. The error message points at the bad constraint.
- **Build-probe stricter.** Projects that relied on probes passing despite stderr noise will now see those probes fail or carry a warning trail. Where the diagnostic is a real compiler error, that is correct. Where it is a benign warning, the trail surfaces it without failing.
