## Verdict labels (5 total)

| Label                | Trigger                                                                                                                                                                      | Rubric-ID prefix |
| -------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------- |
| `PORT`               | Distinct mechanism / idea / spec / constraint that delivers measurable engineering leverage and is not already in arbiter. Will be packaged as **opt-in** module in arbiter. | `R-PORT-NN`      |
| `ALREADY_IN_ARBITER` | Mechanism is already implemented or explicitly catalogued in arbiter. Cite `VIAFERA-ALIGNMENT.md §X.Y` or `arbiter/<path>`. No re-derivation.                                | `R-AIA-NN`       |
| `CERIMONIA`          | Process theatre: document exists for ritual, audit, or status performance — no measurable enforcement, no automation, no consumer outside its own scope.                     | `R-CER-NN`       |
| `REJECT`             | Actively harmful: anti-pattern, false-evidence ritual, governance debt, lock-in, hidden coupling, complexity multiplier. Must NOT enter arbiter under any flag.              | `R-REJ-NN`       |
| `OBSOLETE`           | Superseded inside viafera itself (archived, deprecated, replaced). Useful only as premortem evidence.                                                                        | `R-OBS-NN`       |

**(Note: red-team merged GOLD into PORT. Every arbiter port is opt-in by design — distinction was operationally empty.)**

## Tie-break priority

When ≥2 labels match, apply this order (first wins):

1. `ALREADY_IN_ARBITER` — never re-port. Cite the arbiter source.
2. `OBSOLETE` — if viafera itself killed it, no extraction.
3. `REJECT` — harm beats utility.
4. `CERIMONIA` — ritual beats salvage.
5. `PORT` — fallback when something real survives 1–4.

---

## R-PORT — Trigger conditions

A file/mechanism scores `PORT` only when **all three** hold:

- (P1) Encodes a constraint, schema, contract, or generator-input that **fails closed** when violated (gate, hook, ArchUnit rule, JSON-Schema, OPA policy, lint rule, type, build flag).
- (P2) Is **language- or stack-agnostic** OR can be templated for ≥2 stacks (Java, TS, Go, Python, Rust). Pure Spring/Vue specifics → CERIMONIA unless generalizable.
- (P3) Is **NOT** already in `arbiter/docs/PRODUCT/VIAFERA-ALIGNMENT.md` (grep first). If present → `ALREADY_IN_ARBITER`.

### Examples (calibrated against Tier-1 reads)

- **R-PORT-01** — `viafera/docs/SYSTEM/COMPLIANCE_MAPPING.md:25-68` — ISO 27001 Annex A → tool mapping table. Generic, evidence-first, opt-in via `arbiter.json.compliance.iso27001=true`.
- **R-PORT-02** — `viafera/docs/METHOD/GLOBAL_INVARIANTS.md:60-65` — INV-09 "Privacy by Design (GDPR/NIS2)" → data minimisation + no-PII-in-logs + right-to-erasure cascade. Translates to a GDPR opt-in pack (`arbiter.json.compliance.gdpr=true`).
- **R-PORT-03** — `viafera/docs/SYSTEM/RISK_REGISTER.md` — structured risk register schema (assuming readable). Opt-in via `arbiter.json.governance.risk_register=true`.

- (A2) Or mechanism is already generated by an arbiter template/generator (grep `arbiter/src/generators/`, `arbiter/src/templates/`).

## R-CERIMONIA — Trigger conditions

A file scores `CERIMONIA` when **any one** holds:

- (C1) Documents a process whose only consumer is itself (self-referential SSOT, audit-of-the-audit).
- (C2) Encodes a workflow with no automated enforcement and no recurring consumer (status doc, retrospective, "design complete" without shipped artifact).
- (C3) Duplicates a fact already authoritative elsewhere in viafera (parallel SSOT).
- (C4) Time-decayed: status header dates >90 days old AND content describes "WILL/SHALL" without grep-confirmable enforcement code.
- (C5) Output is human-only narrative; cannot be parsed, gated, or executed.

### Examples

- **R-CER-01** — `viafera/docs/METHOD/NOTARY_SYSTEM.md` — "Delta-Intent-Patch" doc-change tracker. Status: `DESIGN COMPLETE 2026-02-14`. No `viafera.sh notary` command found; no CI hook; consumer is the doc itself. Trigger C2 + C4.
- **R-CER-02** — `viafera/qa-audit/PHASE3D_ERGONOMICS_AUDIT.md` (and the 14 sibling phase reports) — one-shot human-readable audit narrative; no machine-checkable schema, no rerun. Trigger C2 + C5.
- **R-CER-03** — `viafera/docs/METHOD/SSOT_CASTLE_NOTES.md` — meta-commentary about the SSOT system itself. Trigger C1 (SSOT-of-the-SSOT).

## R-REJECT — Trigger conditions

- (J1) Builds lock-in to a vendor / IDE / agent runtime that arbiter explicitly avoids.
- (J2) Mandatory ritual that produces evidence without verifying anything (false-evidence trap).
- (J3) Mixes product concerns with framework concerns (the very disease arbiter exists to cure).
- (J4) Recursive self-reference that prevents either side from maturing.
- (J5) Hidden coupling that defeats arbiter's opt-in principle (e.g. an "optional" module that silently requires 4 others).

### Examples

- **R-REJ-01** — `viafera/arbiter-overlay/` — arbiter applied back onto viafera while viafera is dying. Recursion (J4) + product/framework mix (J3). Do not import the pattern; never overlay arbiter onto a non-greenfield repo via opaque template injection.
- **R-REJ-02** — `viafera/.agents/checkpoints/` + `.agents/cache/` — bespoke agent runtime state. Lock-in (J1) to a homegrown orchestrator with zero portability outside viafera.
- **R-REJ-03** — `viafera/artifacts/gauntlet/2026*/` — 20+ "gauntlet" runs persisted in repo. Evidence-without-verification (J2): nothing fails if a gauntlet directory is deleted.

## R-OBSOLETE — Trigger conditions

- (O1) File path under `99-ARCHIVE/`, `superseded/`, `*.deprecated.md`, `*.OLD.md`.
- (O2) Header explicitly says `DEPRECATED`, `SUPERSEDED BY`, `ARCHIVED`.
- (O3) Replaced by another viafera artifact and the replacement is reachable.

### Examples

- **R-OBS-01** — `viafera/docs/99-ARCHIVE/superseded/*` (15 files) — explicitly superseded inside viafera. Premortem evidence: process produced more dead docs than living ones.
- **R-OBS-02** — `viafera/docs/SYSTEM/SonarCloud-*` references → COMPLIANCE_MAPPING.md flags SonarCloud as _(deprecated 2026-01-18; PMD+SpotBugs are the active replacements)_.
- **R-OBS-03** — `viafera/99-ARCHIVE/claude/` (1 md) — abandoned Claude-specific config.

## Stop signals (apply during scout work)

| Signal                                                           | Action                                                                                                  |
| ---------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| >25% of files in a bucket trigger CERIMONIA                      | Scout stops per-file labeling, emits a single bucket-level note. Bucket goes to premortem as a cluster. |
| Scout returns <50% of expected rows                              | Lead re-dispatches once with stricter prompt; if still shallow → lead reads bucket directly.            |
| File contains secrets / hostnames / emails / Keycloak realm URLs | Quote heading only. Body scrubbed. Apply regex from `00-README.md §Secrets scrub`.                      |
| Per-file verdict not derivable in <60 sec of skim                | Defer to Tier-B (path-only classification). Log deferral in INVENTORY.                                  |

## Per-file table schema (used by all scouts)

```
| Path | LOC | Last commit (date) | Verdict | Rubric-ID | One-line note | Citation |
```

- **Path** — relative to viafera repo root.
- **LOC** — `wc -l` on the file.
- **Last commit** — `git log -1 --format=%cs <path>`. Older than 90 days → CERIMONIA candidate (trigger C4).
- **Verdict** — one of the 5 labels.
- **Rubric-ID** — e.g. `R-PORT-01`, `R-CER-04`. Numeric suffix free-form per scout, prefix mandatory.
- **One-line note** — ≤120 chars, no marketing prose.
- **Citation** — for PORT/ALREADY_IN_ARBITER, mandatory `path:line` proof; for CERIMONIA/REJECT, optional but recommended.

## Anti-cerimonia self-check

The audit itself must not become viafera. Lead checks before finalising:

- Total deliverables ≤6 files (00-README, 00-RUBRIC, INVENTORY, FINDINGS, INTEGRATION, ISSUES/).
- No nested status doc inside the audit.
- No "audit-of-the-audit". If the audit needs a meta-doc to explain itself, it has failed.
