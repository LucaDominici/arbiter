# Context Checker Agent

**Purpose:** Phase-1 of the two-phase verification bridge. Reads `CONTEXT_PACK.md` and the task diff to produce a `REVIEW_CONTEXT` verdict used by the bridge-reviewer in Phase 2.

**Mode:** READ-ONLY

---

## Inputs

1. `CONTEXT_PACK.md` — generated by `arbiter context-pack`, contains track, invariant list, and `@source:` file citations
2. Task diff or file contents for each `@source:` entry in the CONTEXT_PACK

## Protocol

For each file listed under `## Files` in `CONTEXT_PACK.md`:

1. Read the file content
2. Check for violations of each invariant listed under `## Invariants`
3. Record an observation and per-file verdict (`PASS` / `REJECT`)

After reviewing all files, emit a `REVIEW_CONTEXT` JSON block:

```json
{
  "task_id": "<task_id>",
  "track": "<A|B|C|D>",
  "files": [
    {
      "path": "<file_path>",
      "observation": "<one-sentence finding>",
      "verdict": "PASS | REJECT"
    }
  ],
  "invariants_checked": ["INV-XX", "..."],
  "context_verdict": "PASS | REJECT"
}
```

`context_verdict` is `PASS` only if **all** file verdicts are `PASS`.

## Track Invariant Reference

| Track | Invariant Tier                                            |
| ----- | --------------------------------------------------------- |
| A     | Tier 1 — Architectural Integrity (INV-01..INV-06, INV-46) |
| B     | Tier 5 — Governance (INV-21..INV-28)                      |
| C     | Tier 2 + 3 — Data Integrity + Security (INV-07..INV-15)   |
| D     | Tier 4 — Operational Excellence (INV-16..INV-20)          |

## Constraints

- Read-only. Do not modify files.
- Do not run build or test commands.
- Output the `REVIEW_CONTEXT` JSON block verbatim — it is consumed by the bridge-reviewer agent in Phase 2.
