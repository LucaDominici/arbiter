# #2928 — bake-freshness freeze trusts content, not commit order

## Acceptance Criteria

- AC-2928.1: The freeze owes a rebake only when the snapshots are actually stale. It decides this by content (the bake's own drift check at HEAD, or a recorded bake-verified SHA for the current HEAD), not by commit order.
- AC-2928.2: A template change whose bake produces no snapshot diff reaches the review freeze without a synthetic commit.
- AC-2928.3: A template change that does alter a bake lane's output, with stale snapshots, is still refused. The refusal carries the existing remedy.
- AC-2928.4: One regression test for each of AC-2 and AC-3.

## Non-goals

- Running the bake inside the freeze; any `src/templates/**` or bake `__snapshots__` edit (#2913 owns them).
- A new `src/` export or CLI verb.

## Design

See `.claude/plans/PREMORTEM_2928.md` §1.4. A green, non-update, complete `npm run test:e2e:bake` on a
clean tree records `bakeVerifiedSha = HEAD` in existing task state; `checkBakeAfterTemplates` returns
early when that SHA equals HEAD, otherwise keeps the commit-order check and its remedy.

## Test strategy

RED file `__tests__/commands/bake-freshness-content-2928.test.ts` (AC-2928.2, AC-2928.3 incl. stale SHA),
plus the real-flow bake proof and the targeted sweep in PREMORTEM §1.5.
