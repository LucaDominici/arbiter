# #2899 — premortem decision computed at read time

## Acceptance Criteria

- AC-2899.1: A task whose first `ship` call ran without a plan, and whose plan manifest resolves to `deterministic` or `skip-llm`, reaches the review freeze without a `premortem:` reference.
- AC-2899.2: The review-freeze refusal names the rule computed from the current manifest, not a persisted one.
- AC-2899.3: `status.json` no longer carries `premortem`. Existing files that still carry it are ignored, never trusted.

## Non-goals

- Coded refusals for the premortem gate (#2910).
- Changing the premortem rule table in `ship-tier.ts`.
- Removing the tolerated legacy `premortem?` key from the state type.

## Design

See `.claude/plans/PREMORTEM_2899.md` §1.3 and §1.5. The decision is
`evaluatePremortem(current manifest, state.treatment, force?)` at every reader
(`checkPremortemRequired`, `premortemFor`, `premortemLogSuffix`). No treatment → no decision.
`ship --premortem` persists only the input, `premortemForced: true`, which is sticky.

## Test strategy

RED file `__tests__/commands/ship-premortem-read-time-2899.test.ts` (AC-1..AC-3, plus AC-1b force
across processes and AC-3b log suffix). Fixture fixes per premortem §1.6 add manifests, never relax
an assertion.
