# Task #2875 — stale base before review, merge-not-rebase, auto re-derive, task-scoped plan

## Acceptance Criteria

- [ ] AC-2875.1: Before dispatching a review round, `ship` detects that the candidate's base is behind the PR's base branch (`git merge-base --is-ancestor origin/<base> HEAD`). It prints one next action: the exact merge command and the re-anchor command. It does not dispatch a reviewer on a stale base.
- [ ] AC-2875.2: The refactor- and verification-phase guidance states "integrate main with a merge commit, never rebase (TDD evidence pins commit SHAs)".
- [ ] AC-2875.3: When the only change since the plan anchor is a merge of the base branch that leaves the plan's acceptance criteria and preventive-contract authorities unchanged, the derived contract is re-derived automatically, with no manual `lifecycle start`. A change to any contract authority still requires an explicit re-anchor.
- [ ] AC-2875.4: The task plan defaults to a task-scoped path (for example `.claude/plans/<task>.md`) instead of a shared root `PLAN.md`. Existing root plans stay supported.

## Non-Goals

- No automatic merge, no auto-rebase.
- No change to the review cap, the TDD evidence or landing.
- No threshold, baseline or tolerance change; no LLM step.

## Design

- **AC-1**: `assertReviewSubjectFrozen` runs `assertBaseCurrent` after the clean-tree check and
  before the bake check: `git fetch --quiet origin main` (30 s, fail-open to the local ref, same
  as `branchFullyMerged`), then `git merge-base --is-ancestor origin/main HEAD`. The base is
  `origin/main`: it is the lifecycle's landing ref (`isMergeReachable`, direct landing) and the ref
  `cross-model-review.ts` diffs the reviewer against, which is exactly where the stale base reads as
  a revert. Exit 1 throws `E_STALE_BASE` with one next action: `git merge --no-edit origin/main`,
  then re-anchor with `arbiter lifecycle start --id '<id>' --tier <tier> --plan <plan>` only if the
  merge changed a contract authority (`arbiter`, like every other task.ts refusal). The throw
  precedes the state write, so no round is recorded and no reviewer is dispatched. Missing ref
  (exit 128): skip, exactly like today.
- **AC-2**: the exact phrase "integrate main with a merge commit, never rebase (TDD evidence pins
  commit SHAs)" in the refactor step (`prepare`) and verification step action of
  `task-ship.ts`, in the `RECOVERY_TABLE` refactor and verification entries of `task.ts` (printed
  by `lifecycle resume`), and in `## Gate economy` of both ship.md copies. One non-exported
  constant per source file (publicApi unchanged).
- **AC-3**: `lifecycle start --plan` also stores `derivedGatesPlan` (sha256 of the plan file,
  fragment stripped; empty when not written yet). When `--check-derived-current` refuses,
  `checkPlanContractCurrent` re-derives in place only if the plan still hashes to
  `derivedGatesPlan`; if the fresh authority differs from the stored one it restores the stored
  record and the original refusal stands, otherwise it re-runs the checker once. Happy path costs
  nothing (re-derive only after a refusal). `review` is never touched.
- **AC-4**: the preflight step prints the same anchor command as the plan step
  (`--plan .claude/plans/task-<N>.md`, anchored plan wins) from one helper; the ship.md Plan step
  names the task-scoped default. A root `PLAN.md` anchored earlier is still honoured.
