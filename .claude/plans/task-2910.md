# #2910 — coded refusals for the runtime delivery-path refusals hit in C26–C28

## Acceptance Criteria

- AC-2910.1: A stale native host binding in the lifecycle CLI refuses with a stable error code, never through the CLI's `Unexpected error:` branch. The message names the field that no longer matches (session, worktree, branch or task) and gives the exact `lifecycle preflight` command as the remedy.
- AC-2910.2: When the `complete` gate refuses because main does not equal the PR head under the `exact-pr` completion policy, the refusal has a stable code, names both SHAs, and says that a merge-commit merge cannot satisfy `pr-ff` completion.
- AC-2910.3: At phase `close`, the next action printed by `ship` names the landing command for the configured merge mode. For `pr-ff` that is the fast-forward lander, `scripts/pr-merge-watch.mjs <owner/repo> <pr>`.
- AC-2910.4: `ship --review-round` without a configured reviewer seat says, in its first output line, that no reviewer was dispatched and that the round waits for an independent reviewer envelope, before printing the template.
- AC-2910.5: One test per refusal above asserts that stderr starts with its code, and that none of them reaches the `Unexpected error:` branch.

## Non-goals

- Converting all 141 delivery-path throws. Only the refusals hit are in scope.
- Script and template refusals (the companion issue).
- Removing the host binding (roadmap step 3).
- Widening `closeAction` to peer-review/gated-review (they land by a normal PR merge).

## Design

See `.claude/plans/PREMORTEM_2910.md` (GREEN pseudo-diff). `E_STALE_HOST_BINDING` from both
native-binding asserts, with the stale field; `E_PR_NOT_MERGED` from `prGateRefusal`, with the
`exact-pr` detail naming the PR head and merge commit SHAs; a `reviewNote` on the no-seat review
round printed as the first line before the template. AC-3 is unchanged code, pinned by a test.

## Test strategy

RED file `__tests__/commands/coded-refusals-2910.test.ts` (AC-1, AC-2, AC-4, AC-5 for AC-1).
GREEN-side pins: AC-5 for AC-2 in `pr-merged.test.ts` (`E_PR_NOT_MERGED` through `runTaskAdvance`),
AC-3 in `ship-review.test.ts` (trunk-solo/pr-ff close names the lander).
