# #2885 — completion guard: negation-aware, treatment-floor, re-entry-safe

Branch: `task/#2885-completion-guard`, base `origin/main` `3debcf27`.

## Acceptance Criteria

- [ ] AC-2885.1: A stop message that reports status or a handoff, without asserting completion
      (including negated or quoted completion phrases), is not blocked.
- [ ] AC-2885.2: The reviewer-count floor comes from the task's persisted ship treatment
      (`agents-dispatched.json` `count` versus the treatment's panel total), not from a
      hardcoded 4.
- [ ] AC-2885.3: A real completion claim while the phase is not `complete`, or with a missing or
      insufficient review, is still blocked (the existing guarantee is preserved).
- [ ] AC-2885.4: When `stop_hook_active` is true and nothing changed since the previous block, the
      hook does not block again.
- [ ] AC-2885.5: The template and the self copy are byte-identical, and the bake snapshot hashes
      are updated.

Interpretation note (not part of the frozen criterion text): the template carries EJS tokens
(`<%= projectName %>`, `<%= testCommand %>`) and cannot be literally byte-identical to the self
copy — AC-2885.5 is read as "the pinned `.dogfood-divergences.json` diffHash for this file is
re-pinned to the new content", stated on the issue/PR for reviewer sign-off.

## Non-Goals

- No removal of the guard, no change to review policy, lifecycle phases, or landing.
- No change to `lib.mjs` (avoids a 27-snapshot rebake and an export-surface re-pin).
- No change to the `COMPLETION_PATTERNS` literal (pinned by
  `completion-patterns-sync.test.ts`); negation/quote logic lives in a wrapper around it.
- `stop-evidence-guard.mjs` is out of scope unless the Stop-chain test proves the fixed message
  still re-blocks there — if so, a one-line classifier swap is added and declared in the PR, not
  a broader rework.
- No new completion-phrase corpus entries beyond the ACs' negation/quote cases.

## Facts that shape the diff (premortem, verified against `git show origin/main`)

1. Every warning is informational — the hook blocks on any `COMPLETION_PATTERNS` hit in an impl
   phase (`guard-task-completion.mjs:72-103`). AC-2885.2 is a message-accuracy fix; the exit path
   for AC-2885.3 is untouched.
2. `.agents-dispatched` (plain int) has no writer on main; native Ship writes
   `.arbiter/agents-dispatched.json` `{taskId, count, agents, treatmentHash, branch, sha}`
   (`src/commands/cross-model-review.ts:322-374`). The panel total lives in
   `.claude/.task/status.json` `treatment.finalReviewers` (`ship-tier.ts:41-54`).
3. `stop_hook_active` is never read today — the guard always blocks. Existing test
   `completion-guard.test.ts:217-226` asserts exit 2 on re-entry and must be rewritten (not
   deleted) into the AC-2885.4 cases.
4. Template and self are not byte-identical (`.ejs` carries `<%= projectName %>` /
   `<%= testCommand %>` tokens and imports `getRepoRoot`/`readTaskState` from `lib.mjs`; self
   inlines them). The contract is the pinned `diffHash` in `.dogfood-divergences.json:48-52`.
   AC-2885.5 is satisfied by re-pinning, stated explicitly in the PR body.
5. `completion-patterns-sync.test.ts` pins the `COMPLETION_PATTERNS` literal identical across
   guard self+ejs and stop-evidence-guard self+ejs. Literal stays untouched.
6. Stop chain order (`hooks.mjs:44-50`): skill-forced-eval, guard-task-completion,
   guard-done-evidence (flag-gated), stop-evidence-guard (already exits 0 on
   `stop_hook_active`, same regex, no negation awareness), stop-finding-loss. First non-zero exit
   aborts the chain — a message that passes the fixed guard can still be re-blocked by
   stop-evidence-guard on the same regex.
7. Coverage ratchet floor is 90.01 (hooks are not instrumented, so unaffected unless `src/**`
   changes). Fail-closed audit grandfathers both target files until 2026-11-29. docs-check trips
   because `src/templates/**` and `__tests__/**` change — `HOOK-CONTRACTS.md` row updated in the
   GREEN commit.

## Design decisions

- (a) AC-2885.1 via a sentence-level classifier (`isCompletionClaim`) local to the guard, both
  copies, `COMPLETION_PATTERNS` literal unchanged.
- (b) AC-2885.2 reads the sidecar JSON + status treatment; no numeric fallback to 4.
- (c) AC-2885.4 copies the #2861 session-marker pattern verbatim (marker under `.claude/.task/`,
  gitignored).
- (d) No `lib.mjs` change.
- (e) `stop-evidence-guard.mjs` touched only if the chain test proves it re-blocks the delivery8
  idx-405 message; declared here as a conditional, pre-approved one-line swap.
