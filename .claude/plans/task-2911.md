# #2911 — coded refusals for the script/template refusals hit in C26–C28

## Acceptance Criteria

- AC-1: The recorder's stale-binding refusal names the one check that failed (task, branch, sha, or the specific binding field), and gives `lifecycle preflight` as the remedy when the binding is the cause.
- AC-2: When the ac-fit artifact is missing because the reviewer returned NOT-TESTED, `check-acceptance` lists those criterion ids and gives both remedies: the `[exact-main]` marker for a CI-only criterion, or an independent verifier envelope.
- AC-3: The stale-derived-gates refusal names which derived input changed (plan bytes, manifest, or a contract authority file).
- AC-4: Runtime and emitted twins stay identical, verified by the existing self-dogfood and bake checks. One test per refusal asserts its signal and remedy text.

## Non-goals

- Removing persisted derived gates. That is the read-time cut that closes #2901/#2902.
- An error catalog or `arbiter explain` linkage for scripts; no new CLI option.
- Any `src/` change outside `src/templates/scripts/`.

## Design

See `.claude/plans/PREMORTEM_2911.md` §1.4. `assertModeIdentity` returns the one stale cause
(task → branch → sha → binding, binding text from the hook library verbatim); `modeContext` names it and
adds the `lifecycle preflight` remedy only for binding causes. `checkExplicitFitArg` reads the task's
latest reviewer envelope with `acceptanceFit` and lists NOT-TESTED ids with both remedies.
`checkPlanDerivedGates` appends the cause (never anchored / plan bytes changed / verification authority
changed / manifest-derived gate set changed) to the unchanged prefix. Identical edits in each twin.

## Test strategy

RED file `__tests__/scripts/coded-script-refusals-2911.test.ts` (AC-1, AC-2, AC-3; each asserts signal
and remedy). AC-4: twin `diff` empty, `examples:check`, `check-self-dogfood`, bake snapshots.
