# #2900 — non-string skeptic verdict must not count toward the refutation quorum

## Acceptance Criteria

- AC-2900.1: a verdict that is not one of the allowed verdict strings (for example an array, a number or an object) is rejected, not coerced, and does not count toward the quorum. The fixture above exits 1.
- AC-2900.2: a regression test pins the case.

"The fixture above" is the issue's reproduction: `refutation-required.json` `{"task":"#300","skeptics":3,"findings":["F-300"]}` plus 3 skeptic envelopes whose refutation verdict is `["UPHELD"]`.

## Non-goals

- Any change to `main()` or `unaddressedAboveFloor()` (pre-existing complexity is in the baseline).
- Widening or re-anchoring the verdict regex; any change to exit codes or messages.
- A new `src/` export.

## Design

See `.claude/plans/PREMORTEM_2900.md` §1.4. `envelopeVerdict(env, id)` keeps a refutation only when
`typeof r.verdict === 'string'` and it matches `^(UPHELD|REFUTED)$`; both callers route through it.
Identical edit in `scripts/check-refutation-verdicts.mjs` and its `.ejs` twin; bake snapshots
java-spring-L3/L4 regenerated. One line in `docs/design/agent-return-provenance.md`.

## Test strategy

RED file `__tests__/scripts/refutation-verdict-type-2900.test.ts` spawns the real script on the issue
fixture: array ×3 → exit 1 (AC-2900.1, AC-2900.2); number and object → exit 1 (guards); string `UPHELD` ×3 → exit 0
(control). Existing pins `check-refutation-verdicts.test.ts` and `-render.test.ts` unchanged; twins `diff` empty.
