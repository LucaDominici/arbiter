# #2934 + #2935 — tests stop writing into the tree; refutation fixture pins its root

## Acceptance Criteria

- AC-2934.1: `wiki-migrate-1244.test.ts` no longer writes into the repository tree. It uses a temporary copy or a temporary root for the residue case.
- AC-2934.2: No test under `__tests__/` creates files in tracked repository directories during a run. One guard test fails if one does (for example, a `git status --porcelain` check after the suite in a dedicated project, or a lint on `writeFileSync(r(...))` in tests).
- AC-2935.1: The `refutation-verdicts` fixture pins its own repo root (or task context), so the checker evaluates the planted fixture no matter what task state the host checkout has.
- AC-2935.2: `check-guard-flip` passes in a worktree with an active task, and a regression test plants a host `.claude/.task/status.json` to prove it.

## Non-goals

- Any `src/`, template, example or bake snapshot change.
- A runtime whole-tree `git status` sandbox (it cannot see a write already removed in `afterAll`).
- Adding `--repo-root` to other `file-scan` registry fixtures (follow-up issue if needed).

## Design

See `.claude/plans/PREMORTEM_2934.md` §1.3 and §1.5. #2934: the #2643 residue case moves to a tmp
git repo (`trackedExists` takes `cwd`); a static scan test flags any `__tests__/**/*.test.ts` that
writes via its `ROOT`/`r()` helper without a tmp root (lexical ceiling named in the test).
#2935: the `refutation-verdicts` fixture passes `--repo-root <fixture dir>`.

## Test strategy

RED files `__tests__/scripts/no-tree-writes-2934.test.ts` (AC-2934.1, AC-2934.2) and
`__tests__/scripts/guard-flip-host-task-2935.test.ts` (AC-2935.1, AC-2935.2; plants the host task in
a tmp copy of the checker, never in the real `.claude/.task`), plus `wiki-migrate-1244`,
`check-guard-flip` and `doc-gate-allowlist-2917` in the targeted sweep (PREMORTEM §1.6).
