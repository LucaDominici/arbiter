# Plan: ship-tier graph coverage excludes doc-only files (#2895)

## Acceptance criteria (verbatim)

- AC-1: Files that the graph never indexes are excluded from the coverage requirement: `.md`,
  the active plan paths and other doc-only extensions. They must still be listed as changed
  files for every other purpose (doc-only detection stays unchanged).
- AC-1-follow-up: the same applies to `.arbiter/evidence/tdd/*.json` — TDD red-phase evidence
  is data every TDD-following task commits, never AST-indexed, and was found (via a real
  unmocked `gatherTierSignals` run against this branch's own diff) to still block XS/S after
  the `.md`-only fix.
- AC-2: A code file absent from the graph still makes qualification incomplete, and the tier
  widens to Standard (fail-closed is preserved).
- AC-3: A regression test reproduces the Viafera shape: a committed plan `.md` plus two covered
  `.sh` files qualifies XS, and adding one uncovered `.sh` widens the tier.
- AC-4: `worktree prepare` prints a one-line hint when `graphify-out/graph.json` is missing or
  stale in the adopted worktree, and names the command (`graphify update .`). Advisory only.

## Approach (deterministic-only, Ship rule 6)

- `gatherTierSignals` filters the graph-coverage candidate set through a new, narrower
  `isGraphUnindexed` classifier (`.md` extension, any path, plus `.arbiter/evidence/tdd/*.json`)
  before calling `gatherGraphSignals`. The existing `documentationOnly` routing check (root-`.md`
  / `docs/`-prefix regex) is left untouched — it answers a different question and AC-1 requires
  doc-only detection to stay unchanged. Code under `docs/` (e.g. `docs/.vitepress/*.ts`) still
  requires graph coverage (AC-2 regression guard).
- No new exports, no `.ejs`/hook/template change.
- `worktree prepare` (`runWorktreeAdopt`) prints an advisory one-liner when the graph is
  missing or older than the adopted worktree's HEAD.
