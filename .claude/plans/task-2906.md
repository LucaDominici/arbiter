# Plan — #2906 Test-Amend rule for a pinned test changed after RED

## Context

The GREEN execution gate (`greenTestPathFailure` in `src/evidence/tdd-reexecute.ts`) refuses any
difference between the current pinned test and the recorded RED blob. This plan replaces that one
refusal with rule [S] from the pre-registered replay (premortem: `.claude/plans/PREMORTEM_2906.md`).
A missing `test_path` and unavailable RED content still refuse as today.

## Acceptance criteria

- AC-2906.1: When the pinned test at head differs from the recorded RED blob and the ORIGINAL test, run at head, passes in 3 of 3 runs, the GREEN gate accepts without any trailer. The head test must still pass as today.
- AC-2906.2: When the original test fails at head in 3 of 3 runs, the GREEN gate accepts only if a commit between the RED commit and HEAD carries a `Test-Amend:` trailer that binds the current head blob of the pinned test and gives a reason. The trailer line fits the conventional-commit footer limit of 100 characters. Otherwise the gate refuses with `E_SPEC_TEST_CONFLICT`, naming the signal (original test path and RED blob, the verdict at head, the missing or stale trailer) and the remedy (add the trailer with a reason, or restore the original test and fix the code).
- AC-2906.3: A crashed, zero-work or skipped original run is never counted as a pass. Mixed results across the 3 runs are refused with `E_SPEC_TEST_CONFLICT`, and the signal says the test is nondeterministic.
- AC-2906.4: Whenever the pinned test changed after RED, including the structural-accept case of AC-1, the frozen review prompt carries one line naming the test path, the RED and head blobs, the class (structural, or Test-Amend plus its reason), and asks the reviewer to rule explicitly on that hunk.
- AC-2906.5: Regression tests pin AC-1..AC-4 on a shell fixture and a vitest fixture, including the Astra counterexample: an incomplete fix plus the weakened assertion is refused without the trailer.

## Non-goals

- CI replay of the rule. The CI checker `check-tdd-evidence` does not pin the head blob today; running [S] in CI belongs to roadmap step 3 (B1, the same check locally and in CI).
- A `subject: test` lane, meta-witness fixtures, or an assertion count (all rejected by the replay).
- The RED failure-signature format (#2898).

## Design

1. `verifyGreenExecution` keeps its order: path check, RED blob availability, then the head run in
   the caller's checkout. The head run is extracted into one helper shared with the original runs.
2. When the current blob differs from the RED blob and the head run passes, the RED blob
   (`git restore --source <red>`) is written to `test_path` in an isolated detached worktree of the
   resolved HEAD SHA (`addDetachedWorktree`, `linkNodeModules`, `removeDetachedWorktree`, `freeTempPath`),
   and the recorded command runs 3 times with the GREEN verdict logic (`greenFailureAfterRun`,
   `greenCliFailure`). Crash, timeout, zero-work and skipped runs count as FAIL.
3. 3/3 PASS → accept, class `structural`. 3/3 FAIL → accept only with a `Test-Amend:` trailer in
   `<RED commit>..HEAD` whose first token is a ≥7-hex prefix of the current blob and whose reason is
   non-empty (class `test-amend`); otherwise refuse with `E_SPEC_TEST_CONFLICT ... FAILS at`.
   Mixed → refuse with `E_SPEC_TEST_CONFLICT ... nondeterministic`.
4. The result object carries the class (`unchanged | structural | test-amend`), the reason and both
   blobs. No new CLI option, no new state file.
5. `frozenReviewPrompt` adds one line after the RED evidence block when the pinned test at the
   frozen head differs from the RED blob. The review path runs no tests; the class is:
   a `Test-Amend:` trailer in `<RED>..<head>` binds the head blob → `test-amend: <reason>`;
   a trailer in range binds another blob → `unverified: Test-Amend binds <old7>, head is <cur7>`;
   no trailer in range → `structural (GREEN replayed the original at refactor entry; not re-run at
   <head7>)`. The GREEN gate is not re-run at review freeze (out of scope; follow-up #2908).
6. `E_SPEC_TEST_CONFLICT` is registered in `ERROR_CATALOG` and documented in `docs/CONTRIBUTING.md`.
   The gate returns plain strings (no `t()` key), so `en.json` needs no entry; `task.ts` already
   passes `result.reason` through.
7. `shellOutputFailure` reuses the shared `framework === 'shell'` pattern from `FAILURE_SIGNATURES`
   (`src/evidence/tdd.ts`, import only) instead of a private copy; a missing entry fails closed.

## Impact

Callers of `verifyGreenExecution`: `src/commands/task.ts` (`checkGreenExecutionGate`) only. The RED
re-execution path (`verifyRedExecution`, called by `src/commands/verify-tdd.ts`) is untouched.
`frozenReviewPrompt` is private to `runShipCrossModelReview`.

## Existing Code Survey (CANON-16)

No new `src/` file. The detached-worktree helpers, verdict helpers and `resolveEvidenceCommit`
already exist and are reused; only one test file is new.

## CANON-25 — the change that turns the gate red

The Astra counterexample: head impl prints 1, the head test weakens `= 2` to `-gt 0`, no trailer.
The original fails 3/3 at head, so the gate refuses with `E_SPEC_TEST_CONFLICT`. Removing the
original replay (accepting any passing head test) turns that case green and the RED test red.
