# #2932 — delivery-path refusals are coded (`E_GATE_REFUSED`), never `Unexpected error`

## Acceptance Criteria

- AC-2932.1: A required checker that exits 1 with a `FAIL` line surfaces as a coded user-facing refusal. It carries the checker's own `FAIL` text, including its remedy, and never `Unexpected error`. Widened (issue comment, 2026-09-26): every refusal on the delivery path that names its remedy throws a coded `UserFacingError` (the #2910 pattern), and none prints `Unexpected error` — `runRequiredTaskChecker` (derived gates stale), the acceptance-anchor gate, `checkBakeAfterTemplates`, and the base-currency check.
- AC-2932.2: A checker that cannot run (missing script, spawn error, timeout, or an exit code other than 0 and 1) still surfaces as a fault, as today.
- AC-2932.3: A regression test for each of AC-1 and AC-2 goes through the real CLI entry point, including the #2903 derived-stale case.

## Non-goals

- The §8 sweep of further plain-`Error` refusals on the delivery path (follow-up issue, reusing `E_GATE_REFUSED`).
- Any change to `scripts/`, `src/templates/`, bake snapshots, or the exit codes of the checkers.
- A new export, CLI option, or writer action; a second error code.

## Design

See `.claude/plans/PREMORTEM_2932.md` §0 and §4: private `gateRefusal` / `checkerFailure` /
`withStdoutFail` helpers in `src/commands/task.ts`; `E_GATE_REFUSED` with i18n text `{detail}` and
an error-catalog row; one bullet in `docs/REFERENCE/ship-driver.md`.

## Test strategy

RED file `__tests__/commands/coded-refusals-2932.test.ts` (7 cases through `dist/cli.js`: four AC-2932.1
sites, the stdout FAIL case, two AC-2932.2 guards), plus the targeted sweep in PREMORTEM §6.
