# #2903 — TS evidence collector coverage command must produce coverage-summary.json

## Acceptance Criteria

- AC-2903.1: the collector's coverage invocation, run against a real generated TS project, produces the summary file the collector reads, and records coverage PASS when thresholds are met.
- AC-2903.2: a test runs the real vitest (no shim) as the positive control.

## Non-goals

- Any change to coverage thresholds or to the fail-closed paths (a missing or stale summary still fails).
- Isolating the collector's `reportsDirectory` (standalone design choice, not a defect).
- A new `src/` export; any change to the non-TS collector branches.

## Design

See `.claude/plans/PREMORTEM_2903.md` §3.4. In `collectCoverage` (TS branch of
`src/templates/scripts/evidence-collect.mjs.ejs`) the argv becomes
`['vitest','run','--coverage','--coverage.reporter=json-summary']`: the reporter value changes to
`json-summary` and the invalid `--reporter=silent` is dropped (stdout is already captured). No runtime
twin exists. One note in `docs/REFERENCE/evidence-summary-schema.md`.

## Test strategy

RED file `__tests__/scripts/evidence-collect-coverage-2903.test.ts` renders the TS L3 collector into a temp
project and runs it with real vitest (no shim): `coverage/coverage-summary.json` exists, no `coverage:` failed
dimension, coverage `{line:100, branch:100}` (AC-2903.1, AC-2903.2). Existing render and check-all tests unchanged.
