# #2908 — GREEN execution gate re-run at the reviewed / landed HEAD

## Acceptance Criteria

- AC-1: The review freeze and the `complete` gate refuse a candidate whose HEAD differs from the SHA at which the GREEN execution gate last passed, unless the gate is re-run at that HEAD and passes.
- AC-2: The GREEN pass records the commit SHA it verified, and that SHA is part of the delivery evidence.
- AC-3: A regression test covers entering `refactor` at X, committing a change to the pinned test at Y, and freezing Y: refused until GREEN passes at Y.

## Non-goals

- A CI replay of GREEN (roadmap step 3, B1).
- A new CLI action, flag, or mandatory writer step (counter C7); a new `src/` export.

## Design

See `.claude/plans/PREMORTEM_2908.md` §2.4. Read-time: whenever committed TDD evidence exists, the review
freeze (`assertReviewSubjectFrozen`, after the clean-tree check) and the `complete` gate re-run
`checkGreenExecutionGate` at the real HEAD. Each pass records `greenVerifiedSha` in task state (record
only, never read to decide); the review log and the `complete ← PR #n MERGED` line carry `green=<sha7>`.

## Test strategy

RED file `__tests__/commands/green-gate-head-2908.test.ts` (real git repo, real `verifyGreenExecution`):
refactor entry at X records X (AC-2); freeze at X accepted; pinned test broken at Y → freeze refused;
restored at Z → accepted and Z recorded (AC-1, AC-3). Targeted sweep per PREMORTEM §2.5.
