```bash

  --name <app-name> \
  --resource-group <rg> \
  --image <registry>/arbiter:<version>

# Kubernetes
kubectl set image deployment/<deployment-name> \
  <container-name>=<registry>/arbiter:<version>
kubectl rollout status deployment/<deployment-name>
```

## § 4 — Post-Deployment Verification

```bash
# Health probes
curl -sf https://<host>/health/liveness  | jq .
curl -sf https://<host>/health/readiness | jq .

# Confirm the deployed version
curl -sf https://<host>/health | jq '.version // .info.version'
```

Expected: HTTP 200, `{"status": "UP"}`, version matches target tag.

Wait 2–3 minutes after deployment before declaring success (allow metrics to stabilise).

## § 6 — Rollback Trigger Criteria

Initiate rollback (`docs/runbooks/rollback.md`) if:

- Error rate > 5× baseline within 5 minutes of deployment
- Health probes fail for > 60 seconds
- Critical user flow fails smoke test
- P99 latency > 3× baseline sustained for > 2 minutes
