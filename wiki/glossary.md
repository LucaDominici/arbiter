# Glossary

Core arbiter terminology. Definitions are intentionally short; follow the linked SSOT for
detail.

- **arbiter** — the governance installer. An `npx` CLI that generates `AGENTS.md`, hooks,
  gates, and CI/CD infrastructure into a target project so it can be developed under a strict,
  AI-assisted workflow.
- **gate** — the quality gate (`node scripts/check-all.mjs`). The set of deterministic checks
  that must pass before commit/push/merge. Tiered: **L1** (fast) and **L2** (full).
- **invariant (INV-NN)** — a hard rule the codebase must always satisfy, catalogued in
  `src/invariants/catalog.ts` and enforced by hooks/gates. Violations stop work.
- **CANON-NN** — a process-level rule (e.g. refactor-first, no orphan TODOs) from
  `docs/SYSTEM/CANON.md`, enforced like invariants.
- **governance level (L1–L4)** — how much governance a generated project gets, from light to
  fully regulated; controls which invariants and gates are emitted.
- **brownfield class** — a maturity classification (gold / light / medium / heavy) of an
  existing codebase, used to scale thresholds so new code is held to gold while legacy code
  ratchets up.
- **archetype** — a project shape (e.g. backend-web, library, CLI, data-pipeline) that, with
  the language, selects the right templates and adapters.
- **adapter** — a stack-specific module that teaches arbiter how to lint/test/build a given
  language or framework.
- **kit** — the bundle of mechanical + intelligent files arbiter installs into a project.
- **gold doc-set** — the canonical documentation every arbiter project must carry, declared in
  `standards/gold-doc-set.yml` and audited deterministically by `scripts/check-doc-set.mjs`.
- **gold report** — the updatable `GOLD-REPORT.md`, regenerated by `scripts/gold-report.mjs`
  from the (code-computed) audits.
- **dogfood** — arbiter applying its own governance to itself; `scripts/check-self-dogfood.mjs`
  verifies arbiter's `.claude/` matches what its templates generate.
- **SSOT** — single source of truth; the one authoritative place a fact lives (config/code),
  which docs point at rather than duplicate.
- **/ship** — the orchestration entrypoint that drives one issue to a merged, reviewed PR.
- **/drain** — the multi-issue sibling of `/ship`: drains the backlog as waves, one wave PR
  merged green per cycle (the `wave-drain` skill).
- **/impact** — opt-in graph-first blast-radius analysis (who depends on X) with a ripgrep
  fallback.
