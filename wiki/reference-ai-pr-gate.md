# AI-PR Gate Reference (INV-91)

**Invariant:** INV-91 — AI-PR human-approval gate
**Enforcement:** `_ai-draft-check.yml` + `_label-on-approve.yml` (generated workflows)
**Governance level:** All (L1–L3)

---

## Overview

Bot-authored pull requests (Dependabot, Renovate, github-actions[bot], AI coding agents) must
receive explicit human approval before merging. This gate prevents automated processes from
merging code without human oversight.

INV-91 extends INV-74 (anti-bot human-approval gate) by adding specific detection of bot
PR authors, not just bot reviewers.

---

## Workflow Mechanics

### \_label-on-approve.yml

Triggers on `pull_request_review` with `submitted` event. Applies `approved-by-human` label when
all three conditions pass:

1. Review state is `approved`
2. Reviewer is not the PR author (`reviewer.login != pr.user.login`)
3. Reviewer is a human (`reviewer.user.type != 'Bot'`)

The label application is idempotent — `gh pr edit --add-label` silently no-ops if the label
is already present.

### \_ai-draft-check.yml

Triggers on `pull_request` events: `opened`, `reopened`, `synchronize`, `labeled`, `unlabeled`.

- If the PR author type is `Bot`: asserts `approved-by-human` label is present; fails if absent.
- If the PR author type is `User`: job condition (`if: github.event.pull_request.user.type == 'Bot'`)
  causes the job to be skipped (counts as success in GitHub).

The `labeled`/`unlabeled` trigger ensures the check re-evaluates immediately when the label is
added, allowing the PR to turn green without a new commit.

## Compliance Rationale (21 CFR §11.10(g))

21 CFR Part 11 §11.10(g) requires that computer systems used in regulated environments provide
audit trails and controls ensuring data integrity. For AI-generated code changes:

- **Audit trail:** The `approved-by-human` label application is recorded in GitHub's audit log
  with the reviewer's identity and timestamp.
- **Access controls:** The label can only be applied by accounts with repository write access,
  and the workflow guards against bot self-approval.
- **Non-repudiation:** The reviewer login is verified to be a human account distinct from the
  bot author, preventing a bot from approving its own PR through an intermediary step.

This gate satisfies the spirit of §11.10(g) by requiring documented human review of automated
changes before they are incorporated into the codebase.

## Troubleshooting

| Symptom                             | Cause                                           | Fix                                                                         |
| ----------------------------------- | ----------------------------------------------- | --------------------------------------------------------------------------- |
| `_ai-draft-check` fails             | Bot-authored PR lacks `approved-by-human` label | Request human review; approval triggers `_label-on-approve.yml`             |
| Label not applied after approval    | Reviewer is a bot account                       | Ensure a human account (not `github-actions[bot]`) reviews the PR           |
| Label applied but check still fails | New commits pushed after approval               | `03-human-approval.yml` revokes the label on new commits; re-request review |
| Check skipped on human PR           | Expected behavior                               | `if: user.type == 'Bot'` condition causes job skip for human-authored PRs   |
