## Test Coverage Requirements

- **Minimum coverage threshold**: 80% line coverage
- All public APIs must have tests
- Tests run in CI on every PR

## Mandatory Test Patterns

Every feature implementation must include tests for each of the following patterns:

| Pattern             | Description                                                        | Required |
| ------------------- | ------------------------------------------------------------------ | -------- |
| Happy path          | The primary success case with valid inputs                         | ✓        |
| Null / empty input  | Behavior when required inputs are absent or empty                  | ✓        |
| Not found           | Resource lookup when the target does not exist                     | ✓        |
| Business rule       | Domain invariant violations (invalid state transitions, etc.)      | ✓        |
| Auth / unauthorized | Access attempt without valid credentials or insufficient privilege | ✓        |
| Tenant isolation    | Data from tenant A must not leak to tenant B                       | ✓        |
| Concurrency         | Concurrent access does not produce incorrect results               | ✓        |

## Test Pyramid

| Level        | Tool              | When       | Coverage Target |
| ------------ | ----------------- | ---------- | --------------- |
| Unit         | language-specific | pre-commit | 80%             |
| Integration  | language-specific | pre-push   | key paths       |
| E2E          | language-specific | CI / L3    | happy paths     |
| Chaos / Soak | language-specific | nightly    | resilience      |

## Review Checklist

Before marking a PR as ready for review, verify:

- [ ] Happy path test exists
- [ ] Null/empty input test exists
- [ ] Not-found test exists
- [ ] Business rule test exists
- [ ] Auth/unauthorized test exists
- [ ] Tenant isolation test exists
- [ ] Concurrency test exists
- [ ] All tests pass locally
- [ ] Coverage threshold met (80%)
